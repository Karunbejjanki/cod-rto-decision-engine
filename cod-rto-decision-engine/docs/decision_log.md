# Decision Log

- **Use an explainable rules score first.** Considered fitting a classifier to the sample. Chose configurable signals because the file contains only six months, 30 duplicate order-ID groups, synthetic-looking values, and no held-out validation. A fitted probability would imply more certainty than the data supports.
- **Do not penalize first-time customers by itself.** First orders are 30.3% RTO versus 22.6% for repeat orders, but most first-time buyers still receive their order; status alone is not actionable evidence. Route first orders using address/contact signals and offer confirmation or prepaid before cancellation.
- **Reserve automatic hold/cancel for combined high-risk evidence.** The configured 72% cutoff is above the approximate 70.4% economic break-even at ₹649 AOV: ₹402.38 expected delivered gross contribution versus ₹169.40 expected RTO cost. Since the score is not calibrated, this is a pilot guardrail, not a production cancellation mandate.
- **Keep prepaid discount at ₹25.** A COD-to-prepaid RTO reduction of 24 percentage points is worth about ₹40.66 in expected avoided RTO cost per converted order; ₹25 leaves ₹15.66 before payment fees and conversion effects. Do not discount every order; only nudge orders routed to that bucket.
- **Make WhatsApp mock opt-in and explicit.** Confirmation YES ships COD; NO cancels; unclear replies request clarification; no reply after 24 hours holds/cancels. In the prepaid nudge, YES creates a mock payment state and dispatch waits for payment; NO keeps COD. The simulator never sends real messages or payment links.
- **Send confirmation promptly and respect language preference.** Production messages should go within five minutes of checkout and before warehouse handoff. Use the customer's saved language preference; Hinglish is only the simulator default because the sample has no language-preference field.
- **Keep LLM optional and subordinate to policy.** Deterministic checks handle number formats, known placeholders, thresholds, and money. An opted-in LLM may interpret Hinglish and address completeness; it can only add a high-confidence name/address flag, never lower risk or choose an action. External processing of name/address requires approval.
- **Show a sample replay instead of inventing yesterday.** The supplied file ends September 30, 2026, while the assignment date is October 30. The dashboard warns that its latest-day view is stale sample data.
- **Protect the sample data.** The CSV contains customer names, phone numbers, and addresses. Keep the repository private or remove/replace the sample before public GitHub access.
